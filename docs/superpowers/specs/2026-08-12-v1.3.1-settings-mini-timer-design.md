# v1.3.1 Settings & Mini Timer Design

## Goal

Improve the v1.3 interaction model without changing its configuration schema or refresh semantics: consolidate management actions into one settings surface and replace idle opacity fading with a compact Mini Timer state.

## Interaction architecture

### Unified entry

Both the userscript menu and the panel use one action: `⚙ 设置 / 管理自动刷新`.

The separate userscript commands for disabling the current page and deleting the current site rule are removed. Those actions move into the management dialog so users do not have to understand three separate entry points before seeing their current state.

### Settings / management dialog

Use a Shadow DOM-contained custom dialog instead of the browser `prompt()` flow for normal configuration.

The dialog shows:

- current effective rule and status;
- interval input in seconds;
- scope selection: exact URL or site;
- primary save action;
- contextual destructive/secondary actions:
  - `停用当前页面` when an exact or site rule affects the page;
  - `删除网站范围规则` only when the current hostname has a site rule.

High-frequency intervals from 1–4 seconds remain supported. Saving such a value requires an inline warning and explicit confirmation inside the dialog before persistence.

Exact URL rules remain higher priority than site rules. Saving a site rule while an exact rule exists must explicitly let the user choose whether to remove the exact override or keep it.

### Mini Timer

The expanded panel remains the primary control surface while the user interacts with it. After 5 seconds of inactivity, it collapses rather than becoming translucent.

Expanded state:

- title and active scope badge;
- remaining time;
- pause/resume;
- reset;
- settings/manage button.

Collapsed Mini Timer state:

- running: `⏱ 00:04:33`;
- paused: `⏸ 00:04:33`.

The Mini Timer stays fully legible and visually lighter through reduced padding/background/shadow rather than low opacity.

The panel expands on pointer hover, click/tap, focus, or keyboard interaction. It must remain expanded while dragging, while the settings dialog is open, or while focus is inside the control. On touch-first interaction, tapping Mini expands it; clicking/tapping outside collapses it when safe.

### Dragging and responsive behavior

Dragging remains available through the expanded header. The saved host position continues to be clamped to the viewport. Collapsing must not change the saved anchor unexpectedly.

On narrow screens the settings dialog becomes a centered or bottom-aligned card with viewport-safe margins. It must not depend on site CSS.

## Data and behavior compatibility

No configuration schema bump is required. Continue using `autoRefreshConfig_v2` and preserve:

- v1/v1.2 migration;
- exact > disabled > site resolution;
- exact-page exclusion semantics;
- site-rule deletion cleanup;
- absolute deadline countdown;
- pause/resume/reset behavior;
- 1 second minimum interval.

The version is changed to `1.3.1` only after implementation and verification pass.

## Error handling

- Invalid interval input is rejected inline without closing the dialog.
- Storage failures surface an inline/user-facing error and are logged to the console.
- Destructive actions require explicit dialog confirmation.
- The management dialog never silently deletes an exact override when saving a site rule.

## Accessibility

- Dialog uses `role="dialog"`, `aria-modal="true"`, labelled title, and focus management.
- Escape closes the dialog when no destructive confirmation is pending.
- Keyboard focus stays visible.
- Mini Timer is a button-like interactive control with an accessible label.
- Avoid per-second `aria-live` announcements.
- Respect `prefers-reduced-motion` for panel/dialog transitions.
